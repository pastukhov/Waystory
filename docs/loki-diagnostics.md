# Диагностика Waystory через локальный Loki

Workflow **Diagnostic logs** выполняет запросы к Loki на существующем self-hosted runner `waystory`. Loki не публикуется в интернете. Агент запускает workflow через GitHub и скачивает очищенный отчёт; прямой сетевой доступ из облака не требуется.

## Однократная настройка

В Settings → Secrets and variables → Actions репозитория:

| Тип | Имя | Значение |
| --- | --- | --- |
| Secret | `LOKI_URL` | Базовый адрес, доступный runner, например `http://loki.internal:3100`. Без `/loki/api/v1/query_range`, паролей, query string. Допустим префикс reverse proxy. |
| Variable | `LOKI_SELECTOR` | Селектор **только контейнеров Waystory**, например `{container="waystory-waystory-1"}`. Реальные имена меток проверьте в Grafana Explore. Не используйте ID контейнера: после выкладки он меняется. |
| Secret, опционально | `LOKI_BEARER_TOKEN` | Токен для чтения логов. |
| Secrets, опционально | `LOKI_USERNAME`, `LOKI_PASSWORD` | Basic auth, если требуется. Не задавайте одновременно с bearer token. |
| Secret, опционально | `LOKI_TENANT_ID` | Tenant для заголовка `X-Scope-OrgID`, если включена мультитенантность. |

Если Loki не требует авторизации, задайте только адрес и селектор. Значения нужны лишь workflow диагностики, в `.env` приложения и процесс deploy они не передаются.

Promtail должен отправлять stdout/stderr Waystory в Loki, включая контейнеры после пересоздания. Экспорт понимает JSON приложения и JSON Docker с полем `log`. Другие обёртки, например произвольный текстовый префикс, надо разобрать на стороне Promtail. Срок хранения старых логов задаётся в **Loki**, а не этим репозиторием; рекомендуем 30 дней с учётом объёма диска. Отдельный Loki stream/label для `requestId` не нужен: это высококардинальное поле JSON.

## Использование агентом

```sh
gh workflow run logs.yml -R pastukhov/Waystory --ref main -f hours=6 -f place_id=wiki:ru:3682050
gh run list -R pastukhov/Waystory --workflow logs.yml --limit 5
# После завершения конкретного запуска:
gh run download RUN_ID -R pastukhov/Waystory --name waystory-logs-RUN_ID-1 --dir /tmp/waystory-log-report
```

Можно указать `request_id` (UUID из HTTP-заголовка `X-Request-ID`) или `end_utc=2026-10-17T12:00:00Z`. Окно: 1, 6, 24 или 72 часа; запросы доступны в пределах последних 30 дней, если их хранит Loki. При выборе места сначала находятся его request ID, затем выгружаются связанные события, включая запросы к провайдерам, проверку и итоговый HTTP-ответ. При одновременном указании места и request ID должны совпасть оба.

Без фильтра выгружается поток диагностических событий Waystory за период. Без настройки адреса/селектора workflow завершится с понятной ошибкой, без обращения к случайному серверу. Workflow запускается только на main и не перезапускает приложение.

## Содержимое отчёта

- `summary.json`: окно времени, фильтры, число выгруженных/отброшенных событий и признак `truncated`.
- `events.jsonl`: время Loki, request ID, этап, HTTP-код, продолжительность, результат. Новые события также содержат версию приложения, модель, место и номер попытки проверки.
- `waystory_review_detail`: `supported`, `model_rejected`, `missing_evidence`, `provider_error`, `incomplete_response`, `invalid_json`.
- Для `model_rejected` модель может указать индексы блоков (с нуля) и категории `unsupported_claim`, `contradiction`, `wrong_object`, `regional_context`. Это объяснение проверяющей модели, не независимое доказательство ошибки.
- `missing_evidence` означает отсутствие допустимой точной цитаты хотя бы для одного блока, даже если модель ответила `supported=true`.
- Сетевые исключения/отмена дополнительно видны в событиях этапа `review` и провайдера.

Артефакт хранится в GitHub 7 дней и доступен согласно правам репозитория. После отправки временные файлы на runner удаляются. Loki остаётся источником полной истории: повторная выгрузка возможна в пределах его retention.

Экспорт **не является копией сырых логов**. Он восстанавливает только известные поля диагностических событий. Тела запросов и ответов провайдеров, тексты рассказов, цитаты, фото, cookies, ключи, произвольные сообщения и метки Loki не выгружаются. Поэтому старый журнал не позволяет восстановить конкретный отклонённый текст. Диагностика причин начнёт заполняться после выкладки новой версии.

Один запрос ограничен 5000 исходными строками и 16 MiB, выборка по месту — 50 request ID. При достижении лимита отчёт отмечается `truncated`; сузьте период или запросите конкретный request ID. Не считайте пустой/обрезанный отчёт доказательством отсутствия ошибок. `discarded` помогает заметить несовместимый формат логов. Ротация Docker на сервере не определяет сохранность уже доставленных в Loki записей.

## Проверка реального подключения

После заполнения настроек: запустите workflow за последний час, убедитесь, что есть известные запросы Waystory. Откройте место в приложении и найдите его request ID в отчёте; повторите выгрузку по этому ID. Затем проверьте период до последней выкладки — это проверяет сохранность истории при пересоздании контейнера. До этой проверки наличие Loki и Promtail не гарантирует, что нужные логи действительно доставляются.

## Поиск неизвестных меток

Режим `discover` получает имена меток через Loki API и делает ограниченный поиск событий `waystory_`. Селекторы предлагаются только для потоков с распознанными диагностическими событиями приложения; сырые строки не публикуются. В `discovery.json` появляются имена меток и подходящие селекторы. Пути файлов и container ID помечаются нестабильными: после пересоздания контейнера они могут измениться. Поиск ограничен шестью метками и 100 строками на запрос; отсутствие результата не доказывает отсутствие логов.

```sh
gh workflow run logs.yml -R pastukhov/Waystory --ref main \
  -f mode=discover -f hours=24 -f loki_url=http://LOKI_HOST:3100
# После получения селектора можно сразу проверить выгрузку:
gh workflow run logs.yml -R pastukhov/Waystory --ref main \
  -f mode=logs -f hours=1 -f loki_url=http://LOKI_HOST:3100 \
  -f 'selector={container="waystory-waystory-1"}'
```

Переданный при запуске адрес виден в настройках запуска и используется только при отсутствии Secret `LOKI_URL`. Он допустим для подключения без авторизации. Если заданы секреты авторизации или tenant, сначала настройте доверенный Secret `LOKI_URL`: временный адрес не может получить эти данные. Настроенные `LOKI_URL` и `LOKI_SELECTOR` имеют приоритет над вводом workflow. Для постоянного использования сохраните найденный стабильный селектор в Variable `LOKI_SELECTOR`.


## Если скачивание артефакта недоступно

Те же очищенные события дублируются в журнале запуска как JSON `{"event":"waystory_log_export","record":...}`. Их можно получить командой `gh run view RUN_ID -R pastukhov/Waystory --log` и сохранить локально для анализа. Сырые строки Loki не выводятся; действуют те же фильтры и лимиты. Артефакты хранятся 7 дней, а журнал запуска — согласно настройке retention GitHub Actions репозитория. Для разбора одного сбоя используйте request ID, чтобы сократить объём отчёта.
