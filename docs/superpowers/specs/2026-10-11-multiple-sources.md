# Waystory: несколько источников информации

Статус: предложение для реализации Sol; пользователь поручил подготовить план. Продуктовый код этим документом не меняется.

## Цель и границы

Пользователь идёт по городу, видит объект и получает содержательный рассказ, может менять подробность и задавать вопросы. Сейчас Wikipedia одновременно определяет, какие места существуют поблизости, и ограничивает весь материал рассказа. Нужно отделить поиск объектов от сбора сведений о них.

Первый выпуск: Wikipedia + OpenStreetMap + Wikidata + Wikivoyage. Затем опциональный поиск по официальным сайтам через Tavily. Google Maps Grounding Lite — отдельная интеграция после проверки условий и настройки ключа. Tripadvisor Terra, Lonely Planet и forum.awd.ru не включаются автоматически: это будущие лицензируемые источники.

Успех: объекты без статьи Wikipedia появляются рядом; пользователь видит русское/английское имя и доступное местное написание; источники исторических утверждений доступны из рассказа; отсутствие материала не превращается в выдуманные подробности. Наличие места на карте само по себе не означает, что о нём есть рассказ.

## Решения

1. Координаты, имена и идентификаторы живут в единой карточке места. Имя из английской Wikipedia нельзя автоматически называть местным. `nativeName` заполняется только из явно маркированного источника: OSM `name` как локальное имя по соглашению OSM или Wikidata P1705. Сохраняются происхождение и язык, если известен. Перевод ИИ никогда не перезаписывает исходное имя.
2. Сервер собирает сведения через адаптеры. Браузер не получает ключи и не передаёт произвольный URL для скачивания сервером. Для первого выпуска предпочтительны REST API; обязательного MCP SDK нет. Интерфейсы адаптеров позволяют позднее добавить MCP без смены карточек и генератора.
3. Дедупликация по совпадающим идентификаторам допустима. Похожие названия и близкие координаты сами по себе не основание объединять мечеть, район и одноимённую остановку. Противоречащие координаты остаются явным конфликтом, не усредняются.
4. Каждый материал имеет URL, язык, источник, тип, область применимости, дату получения, дату публикации (если известна), лицензионную политику и атрибуцию. Дата скачивания не считается датой актуальности информации.
5. История/архитектура, текущие условия посещения, легенды и отзывы различаются. Региональный путеводитель не становится доказательством факта о конкретном здании. При противоречии модель должна сообщить о нём или исключить спорный факт.
6. Источники передаются модели как недоверенные данные. Они не могут задавать инструкции, выбирать инструменты, запрашивать секреты или менять системный prompt. Модель возвращает только ссылки на выданные сервером source ID, не произвольные URL.
7. Ссылки и лицензионная информация показываются в карточке и у блоков рассказа/ответа. Их не нужно зачитывать в каждом аудиофрагменте. Старый `source` сохраняется для совместимости с библиотекой.
8. `Коротко → Обычно → Подробно` остаётся накопительным рассказом. Пустой источник не заполняется общими фразами. Дополнительный поиск — по явному действию пользователя; изменение подробности само по себе не запускает новые платные запросы.
9. Сбой нового провайдера не скрывает результаты остальных. Если нет сведений, остаются название, карта и честное сообщение об отсутствии материала. Нулевая выдача и ошибка провайдера различаются.

## Ограничения

- Node.js 22 и 24, JavaScript ESM, текущий интерфейс без нового frontend-фреймворка.
- Языки интерфейса и рассказа: `ru`, `en`. Источники первого выпуска: `ru`, `en`, `tr`.
- Google login и список приглашённых сохраняются. Для вошедших пользователей сохраняется отсутствие пользовательских дневных/часовых лимитов AI/TTS.
- Лимиты параллелизма, размера запросов и независимый общий бюджет нового платного поиска сохраняются; не выдавать этот бюджет за пользовательский лимит рассказов.
- Ключи только на сервере. CI не обращается к платным API.
- SQLite с `node:sqlite`; не добавлять PostgreSQL, Redis, векторную БД или crawler всего интернета.
- Логи не содержат координат прогулки, текста вопросов, полного содержимого источников, email, cookie или ключей.
- Библиотека остаётся в localStorage. Миграция старых записей обратимо дополняет поля; не удаляет историю и избранное.
- Операции и развёртывание — через существующий GitHub runner; SSH от пользователя не требуется.
- Для production использовать лицензии конкретных материалов. CC0 Wikidata не распространяется на тексты Wikipedia; ODbL OSM и CC BY-SA Wikimedia требуют своей обработки. Публичность официального сайта не равна разрешению на массовое копирование.

## Проверяемый выпуск

Три сохранённых набора данных: туристический центр Аланьи, район с редкими POI, объект вне Турции. Проверять корректность объединения, исходные имена, качество привязки материалов и поведение без Wikipedia. Нельзя обещать одинаковое покрытие всех стран.

Приёмка включает отказ одного/всех провайдеров, отмену поиска при смене объекта, конфликт координат, старую библиотеку, мобильные ширины 320/390/780 px, блокировку анонимных платных вызовов, ограничения прав на сохранение и обработку материала.
